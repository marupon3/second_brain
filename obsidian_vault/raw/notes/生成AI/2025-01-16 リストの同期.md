# リストの同期

木曜日
4:42
以下では、Microsoft Lists（内部的には SharePoint
リストと同様）同士を同期するための例を示します。トリガーを「アイテムが作成されたとき」、「アイテムが変更されたとき」、「アイテムが削除されたとき」の3つに分けてフローを作成します。
ここでは、「同期元リスト」を SharePoint 上の Aリスト、「同期先リスト」を
Bリストと呼んで説明します。Aリストで発生した作成・更新・削除を Bリストに反映させる例です。
前提
•        Aリストと
Bリストの構造(列名)は同じ、または同期したい列がそれぞれ存在していること。
•        Power
Automate ポータル( <https://make.powerautomate.com/>
)にアクセスできる権限を持っていること。
•        Aリストと
Bリストの SharePoint サイトURL・リスト名がわかっていること。
1. アイテムが作成されたときのフロー
フローの作成
1.        Power Automate のポータルにアクセスし、「クラウド フローを作成」→「自動化されたクラウド
フロー」を選択します。
2.        フローの名前を例として「AリストからBリストへ_作成時同期」とします。
3.        「フローのトリガーを選択してください」の欄に「SharePoint - アイテムが作成されたとき」(英語の場合: When an item
is created) を選択します。
4.        「サイトのアドレス」、「リスト名」をそれぞれ
Aリストのものに設定します。
アクションの追加 - Bリストへのアイテム作成
1.        新しいステップを追加し、「SharePoint - アイテムを作成」(英語: Create item) を選択します。
2.        「サイトのアドレス」で Bリストのサイトを選択し、「リスト名」で Bリストを選択します。
3.        Bリストの作成したい列に、トリガーで取得した
Aリスト側の動的コンテンツを割り当てます。
•        例えば「タイトル」列など、同期させたい列をマッピングします。
フローの保存とテスト
•        右上の「保存」ボタンを押したら、テストを行います。Aリストに新しいアイテムを作成すると、自動的にBリストにもアイテムが作成されることを確認してください。
2. アイテムが変更されたときのフロー
フローの作成
1.        再度「自動化されたクラウド フロー」から新規作成します。
2.        フローの名前を例として「AリストからBリストへ_変更時同期」とします。
3.        トリガーに「SharePoint - アイテムが変更されたとき」(英語: When an item is
modified) を選択します。
4.        「サイトのアドレス」「リスト名」を
Aリストのものに設定します。
アクションの追加 - Bリストのアイテムを探す
1.        新しいステップで「SharePoint - アイテムの取得」(英語: Get items) または「SharePoint - アイテムの一覧を取得」(英語: Get items)
を使用し、Bリスト内に対応するアイテムがあるかを探します。
•        その際、同じIDや一意のキーがある場合は
OData クエリなどで絞り込むこともできます(例: Title
eq '@{トリガー出力のタイトル}' など)。
条件分岐 - アイテムの有無で処理を分ける
1.        「アイテムの取得」の後ろに「条件」(英語: Condition)
アクションを追加し、Bリストから返ってきたアイテム数が0かどうかで分けます。
•        0でなければ(つまり既にある)→
Bリストで該当のアイテムを更新
•        0であれば(つまりまだ存在しない)→
Bリストにアイテムを作成(必要に応じて)
アクション1 - Bリストのアイテムを更新
1.        条件が「存在する場合」の中で新しいステップを追加し、「SharePoint - アイテムを更新」(英語: Update item) を選択。
2.        Bリストのサイト/リスト名を設定し、アイテムID に検索で得たアイテムの ID を入力します。
3.        同期させたい列をトリガーからの動的コンテンツにマッピングします。
アクション2(必要なら) -
Bリストに新規アイテムを作成
•        「存在しない場合」の分岐の中に、「SharePoint - アイテムを作成」を使って必要データを作成します。
フローの保存とテスト
•        フローを保存し、Aリストのアイテムを変更してみて
Bリストも更新されるか確認します。
3. アイテムが削除されたときのフロー
フローの作成
1.        同様に「自動化されたクラウド フロー」から新規作成します。
2.        フローの名前を「AリストからBリストへ_削除時同期」とします。
3.        トリガーに「SharePoint - アイテムが削除されたとき」(英語: When an item is
deleted) を選択します。
•        もし「削除されたとき」のトリガーが見つからない場合は、SharePoint
のコネクタのバージョンやプレビュー設定を確認してください。
アクションの追加 - Bリストのアイテムを削除
1.        新しいステップで「SharePoint - アイテムの削除」(英語: Delete item) を使用します。
2.        Bリストのサイト/リスト名を指定し、「アイテムID」に対する情報を取得する必要があります。
•        ただし、「When
an item is deleted」のトリガーでアイテムIDなどが取得できない場合があります。その場合は、別途 ID
を管理するために「Aリストにアイテムが作成または変更されたとき」に Bリスト側のアイテムIDを Aリストに保持しておくなどの工夫が必要です。
•        もし削除トリガーで十分な情報が取れない場合は、アイテム削除イベントを検知するフロー設計の見直し(例:
論理削除フラグなど)を検討してください。
フローの保存とテスト
•        フローを保存し、実際に
Aリストからアイテムを削除して Bリストからもアイテムが削除されることを確認します。
まとめと注意点
•        ID管理: Aリストと Bリストのアイテムを関連付けるために、AリストのアイテムIDを
Bリストに書き込む、または逆に BリストのアイテムIDを Aリスト側に保持しておくと、更新や削除で混乱しにくくなります。
•        改名や列追加への対応:
列名が変更された場合や新規列が追加された場合、それに合わせてフローのマッピング部分も修正が必要です。
•        トリガーの動作タイミング:
「アイテムが変更されたとき」のトリガーはアイテムが更新されるたびに動きます。頻繁に更新が走るリストでは不要な処理が多発するので、条件分岐やトリガー条件式を使って最適化しましょう。
これらの手順で3種類のフローを作成すれば、Aリストでアイテムの作成・変更・削除が起こった際に
Bリストへ反映される、基本的な同期が実装できます。慣れてきたら、必要に応じて条件分岐やアクションを追加し、要件に合った同期フローをカスタマイズしてください。
