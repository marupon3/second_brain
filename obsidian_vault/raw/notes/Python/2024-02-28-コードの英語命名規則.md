# コードの英語命名規則

|  |  |  |  |
| --- | --- | --- | --- |
| 記法 | 説明 | 例 | Pythonでの使用 |
| キャメル法 | Pythonでは用いられない | userName |  |
| パスカル記法 | Pascal言語で使われた | UserName | クラス名 |
| スネークケース |  | user_name | モジュール名、メソッド名、関数名、変数名 |
<https://qiita.com/hironori_narita/items/4b06db0953053d41c4a0#2-%E9%96%A2%E6%95%B0>
はじめに
命名フローチャート
変数
関数
クラス
1. 変数
1-1. boolean
1-1-1. 存在するかどうかのフラグ
1-1-2. 表示・非表示
1-1-3. 機能ON/OFFフラグ
1-1-4. 持つ/含むかどうかのフラグ
1-1-5. 基本形
1-2. booleanではない
1-2-1. 日時
1-2-2. その他の変数
2. 関数
・基本形
2-1. 取得
2-1-1. オブジェクトから値を取得
2-1-2. DBなど別の場所から値を取得する
2-1-3. ファイルを読み込む
2-1-4. 条件付きの取得
2-2. 変更
2-2-1. データを変換
2-2-2. 情報の更新（データベースのレコード変更など）
2-2-3. 部分的な修正
2-2-4. 新しいデータで置き換える
2-2-5. 順序や文字の入れ替え
2-2-6. 元の状態に復元する
2-2-7. 誤ったデータを直す
2-2-8. 有効化する
2-2-9. 無効化する
2-2-10. ルールに沿って適用する
2-3. 追加
2-3-1. DBにデータを加える
2-3-2. 配列にデータを加える
2-3-3. 複数のデータを結合する
2-4. 作成
2-4-1.
ルールに基づいて何かを生成する（機械がプログラムのとおりに何かを作り出す場合など）
2-4-2. 新しく作る(何もないところに新しく何かを生み出す)
2-5. 削除
2-5-1. データを削除する場合（もとに戻せない）
2-5-2.
データをアクセス可能な場所から取り除く場合（もとに戻せる可能性あり）
2-5-3.
中身を空にする場合（親となるオブジェクトや変数自体は消えない）
2-5-4.
オブジェクトを完全に破棄する場合（再利用されたり、読み取られたりしないように破却）
2-6. 検査
2-6-1. 要件や性能を満たしているかを調べる場合
2-6-2. 正しく動作しているか確かめる場合
2-6-3. 状態の確認
2-7. 許可
2-7-1. 許可する・権限を与える
2-7-2. 申請を承認する
2-7-3. ユーザーに権限を持たせる
2-8. 禁止
2-8-1. 申請を退ける
2-8-2. 許可を取り消す
3. クラスの命名
・基本形
3-1. ２つの単語を繋げてクラスを作る
3-2. データソースを扱う
3-2-1. Server-Client
3-2-2. APIを叩くためのゲートウェイ
3-2-3. DBにデータを保存
3-2-4. キャッシュする
3-2-5. ログの保存場所
3-2-6. 履歴の保存場所
3-2-7. 設定データの保存場所
3-3. データを加工する
3-3-1. データの絞込
3-3-2. データを抽出
3-3-3. データを整形
3-3-4. データを集める
3-4. データソースをラップする
3-4-1. DB、http 通信、キャッシュ等をカプセル化
3-4-2. データ管理（モデル）
3-4-3. データの読み込み
3-4-5. ログを出力（またはLogクラスへのアクセスを提供）
3-4-6. 設定を保存
3-4-7. データ構造に変更を加える（バージョンアップなど）
3-5. 非同期処理を扱う
3-5-1. 一連の非同期処理を行う
3-5-2. 与えられたJobやTaskを実行
その他気をつけるべき点
不可算名詞をなるべく使わない
二重否定を使わない
クラス名は単数形にする
データ型を含めてもよい
否定形の形容詞を用いる
動詞を複数用いない
