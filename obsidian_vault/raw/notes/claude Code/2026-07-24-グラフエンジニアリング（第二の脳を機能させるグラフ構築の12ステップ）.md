Open your notes folder right now. If it's a flat pile of files, here's what happens every time you ask Fable 5 one question: it reads all of them.  
That's 5,000 notes and 800,000 tokens burned to hand you one answer. slow, expensive, and half the time it still grabs the wrong file.  
That's not a brain. It's a haystack you taught your AI to search.

A second brain is only as good as the graph underneath it. This is the 12-step roadmap to that graph - from a pile the model drowns in to a structure it walks in milliseconds.

- **the pile**: all 5,000 notes read to answer one question  
- **the tokens**: ~800,000 per answer, billed at $50 / million out

## Part 1 · what a graph is

### 1. [ A graph is a routing structure, not a picture ]
Four parts. A router the model reads first, an index it scores against, nodes that hold the knowledge, edges that point between them.  
That's it. Memory, skills, live data - all just ways of shaping one of those four.

The galaxy of dots you posted is decoration. It proves connections exist. It does nothing to stop the model reading 5,000 files to answer one question.  
Same notes, different structure, completely different brain.

Everything that shapes retrieval sits in one directory. Learn this layout and you can read anyone's second brain in ten seconds:

*(Folder layout diagram / description)*

One rule keeps a graph clean: you should be able to say why every file exists.  
Can't explain a node? It shouldn't have one.

### 3. [ Graph vs pile vs system. Three floors, don't stack them wrong ]
- **The pile** is notes in a folder with no map. Ask it anything, it reads everything.
- **The graph** is that same knowledge with a router, an index, and edges. Ask it anything, it reads three files.
- **The system** is a graph with memory that compounds. Every session leaves the next one sharper.

Most "my second brain is a mess" pain is these three tangled together. Untangle them and the whole thing gets fast.

### 4. [ The default second brain is a hoarder, not a librarian ]
Point Fable 5 at a folder and yes, it "works." It finds things by reading the entire pile on every query.  
40 notes? Fine. 4,000 notes? Now every question scans your whole life and bills you at $50 per million output tokens.

A hoarder owns everything and finds nothing. A librarian owns the same books and hands you one in seconds.  
The next eight steps make Fable 5 the librarian.

## Part 2 · build the graph

### 5. [ The router. CLAUDE.md, kept brutally short ]
CLAUDE.md is read at the start of every session. It's a map, not a manual: "billing lives here, this client lives there."

The killer mistake: it grows into a novel. Every session then drags that novel into context before it does a thing.  
Under 500 tokens. Facts and directions only. The knowledge lives in the nodes.

### 6. [ The index. One line per node. This is the secret ]
The index is how the model knows where an answer lives without opening a thing. One line per node: name, link, one sentence.

*(Index example)*

Build one habit from day one: every new note gets a line here, automatically, forever.

### 7. [ Nodes. One idea per file. No exceptions ]
A node does one job. Small, sharp, named so the title alone tells you what's inside.  
The enemy is the mega-note - the 4,000-word file that touches ten topics. To use one line of it, the model swallows all ten.

Split by idea. Small nodes are cheap to open. Fat ones bleed tokens.

### 8. [ Edges. Pointers, not the pretty picture ]
An edge is a link inside a node to another node. That's the real graph - the pointer, not the visual.  
A node answers half your question and links to the one that finishes it. The model follows one edge instead of ransacking the vault.

Link what a node depends on, nothing else. Ten sharp edges is a graph. Fifty is noise wearing a graph's clothes.

### 11. [ Add memory. What the model forgets, the graph remembers ]
The model wipes clean between runs. The graph doesn't have to.  
A state file logs what was tried, what worked, what died. Every run ends by writing to it and starts by reading it.

When a lesson is general, it graduates from the state file into a skill. That's the honest meaning of "self-improving" - not a model that learns, but a graph that accumulates.

### 12. [ Ship it. Portable, and yours ]
The value was never Fable 5. It's the router, the index, the edges, the rules - plain text in a folder you own.  
Every serious model reads markdown, follows a router, walks an index. Unplug Fable 5 tomorrow, plug in whatever's next, lose nothing.

Models are engines. Your graph is the car. Engines get swapped. The car stays yours.

## [ The graph mistakes that keep your AI slow ]

- Running on the flat pile. No router, no index. The model reads everything to answer anything.
- A bloated router. A CLAUDE.md that turned into a manual. Cut it to 500 tokens of pointers.
- No index. Without it the model can't guess where an answer lives, so it opens files blind.
- Mega-nodes. One giant file it has to swallow whole to use one line of. Split by idea.
- Letting the model do the finding. Finding is a code job. Save the model for the thinking.
- No memory. Every run restarts from zero. The state file is what makes tomorrow resume.
- Building the graph before you have notes. Empty structure is busywork. Write first, then engineer.
