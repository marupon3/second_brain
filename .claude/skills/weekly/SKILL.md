# weekly

## When to use

- ユーザーが `/weekly` を実行したとき

## When not to use

- 対象範囲（直近N週）のいずれの週にも`obsidian_vault/daily/`ノートが1件も存在しないとき

## Input

- `obsidian_vault/daily/` 配下のノート。ファイル名の**先頭**が`YYYY-MM-DD`形式であれば、その日付をノートの日付とみなす（例: `2026-08-16 ClaudeObsidian Radar Daily Summary.md`も対象。日付が同じ複数ファイルは同日の複数ソースとして扱う）。
- 走査範囲は**直前に完了した週**（実行日を含む週の1つ前の週。ISO週は月曜始まり）から遡って直近**N週**（既定値: 4週）。ユーザーが実行時に週数を指定した場合はその値を優先する。**実行日を含む週（今週）は、まだ日曜日を迎えていない未完了週のため常に対象外**とする。

## Output

- 対象週ごとの`weekly/YYYY-Www.md`（例: `weekly/2026-W32.md`、ISO週番号）。1回の実行で複数週分を生成・更新することがある。

## 手順

1. 実行日を含むISO週を求め、**その1つ前の週（直前に完了した週）を基準に**、遡って直近N週（既定4週、ユーザー指定があればその値）の対象週リストを作る。実行日を含む週（今週）は、実行日が何曜日であっても対象週リストに含めない。
2. 各対象週について、その週の月〜日の範囲に該当する日付を持つ`obsidian_vault/daily/`ノートが1件以上存在するかを確認する。存在しない週はこの時点で対象外とし、以降の手順を行わない。
3. データが存在する週について、`weekly/YYYY-Www.md`が既に存在するかを確認する。
   - **存在しない場合**: 確認なしでそのまま手順4へ進み新規生成する（未実行週のバックフィルが目的のため）。
   - **存在する場合**: 上書き（overwrite）するかスキップ（skip）するかをユーザーに確認する。対象週が複数ある場合はまとめて1回で確認してよい。skipが選ばれた週は手順4以降を行わず次の週に進む。
4. その週に含まれるdailyノートを収集し、完了・未完了タスク、`## AI生成`セクションの主要トピックを要約する。
5. `weekly/YYYY-Www.md`にWeekly Reviewページを生成、またはoverwriteが選ばれた場合は既存内容を新しい内容で置き換える。
6. 対象範囲の全週の処理が終わったら、`wiki/log.md`に実行結果を1回でまとめて記録する（新規生成した週・overwriteした週・skipした週・データが無く対象外だった週を区別して記載する）。

## 制約

- `obsidian_vault/daily/`配下のノートを編集しない（読み取りのみ）。
- `obsidian_vault/raw/`配下のファイルを編集しない。
- 既存の`weekly/YYYY-Www.md`を上書きする前に必ずユーザーの確認を得ること（無断上書きしない）。
- 追記（append）方式は採用しない。既存ファイルの更新は常に「新しい内容で置き換える（overwrite）」または「何もしない（skip）」のいずれかとする。
- スケジュール実行は行わない。手動コマンド実行のみをトリガーとする（`CLAUDE.md` 5節）。
- 出力は日本語で書く。
- ファイル入出力時はエンコーディングを UTF-8 で明示する。
- コンソール出力以外で絵文字を使わない。
