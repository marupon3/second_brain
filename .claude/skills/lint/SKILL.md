# lint

## When to use

- ユーザーが `/lint` を実行したとき
- Vaultの整合性・鮮度を定期的に確認したいとき

## When not to use

- `wiki/`にページが1件も無いとき

## Input

- `wiki/` `obsidian_vault/daily/` `weekly/` 配下の全Markdownファイル

## Output

- 検出結果のレポート（`wiki/log.md`への追記、および必要に応じて`wiki/lint-report.md`）

## 手順

1. 対象ファイル内の全wikilink（`[[ページ名]]`）を収集し、リンク先ページが実在するかを検証する。存在しないリンクを「リンク切れ」として記録する。
2. どのページからもリンクされていない`wiki/`配下のページを「孤立ページ」として記録する。
3. 同一トピックについて内容が相反する可能性のある記述を検出する。判断が難しい場合は断定せず、AIの所見として記録するに留める。
4. **陳腐化の検出**（下記「陳腐化の検出基準」に従う）。古くなった可能性のある記述を「要再確認」として記録する。**古い＝誤りではない**ため、断定せず候補として挙げるに留める。
5. 検出結果を一覧化し、`wiki/log.md`に追記する。件数が多い場合は`wiki/lint-report.md`に詳細を出力する。

## 事実の3形式と日付スタンプ

`updated:`はページ単位の鮮度しか表さない。ページ全体が新しくても、本文中の1行が黙って嘘になっていることがある。これを防ぐため、**変動する事実は「いつ時点か」を必ず本文に持たせる**。

事実は次の3形式のいずれかで書かれていなければならない。

1. **不変の事実**: 時間で変わらないため日付が不要なもの。
   - 例: 「`obsidian_vault/raw/`は人間のみが書き込む不変ソースである」「PGroongaはPostgreSQLの全文検索拡張である」
2. **時点の記録（スナップショット）**: 日付を添えた観測。「今こうだ」ではなく「その日こうだった」と主張するため、古びても嘘にならない。
   - 例: 「Smart Connectionsは未設定（2026-08-18時点）」
3. **ポインタ**: 現在の値が重要な事実は、値ではなく**真実の所在**を書く。最後に観測した値を併記する場合は日付スタンプを付ける。
   - 例: 「有効なプラグインの一覧は`obsidian_vault/.obsidian/community-plugins.json`が真実の所在。最終観測では`remotely-save`は無効（2026-08-18時点）」

これに対し、**日付スタンプの無い現在形で変動する事実を書く形式だけが禁止**される。これは書いた時点では正しく、しばらく経つと正しく読めるまま嘘になる唯一の形式であり、この基準はそれを見つけるために存在する。

- 禁止例: 「新規の原因不明な消失は今のところなし」「未処理ファイルは残り約30件」「作業ブランチは`origin`に追随済み」

**日付スタンプの記法**: `（YYYY-MM-DD時点）`を標準とする。文中に自然に埋め込む場合は`YYYY-MM-DD時点で`の形も可とする。外部由来の事実は出典を併記する（例: `（2026-08-18時点、docs.anthropic.com）`）。

**日付コンテナは検査対象外**: 日付が前提になっている場所に書かれた事実は、すでにスナップショットとして成立している。以下は変動する事実が現在形で書かれていても指摘しない。

- `wiki/log.md`、[[session-archive|セッション作業アーカイブ]]、`obsidian_vault/daily/`配下、`weekly/`配下のファイル全体
- `- YYYY-MM-DD:` で始まる行、および日付を含む見出しの配下

## 陳腐化の検出基準

「いつの事実か」を問えない記憶は信頼できないため、以下の観点で古びた可能性のある記述を洗い出す。

1. **frontmatterの`updated:`の形式と鮮度**
   - `updated:`が無いページ、および`YYYY-MM-DD`形式（ISO 8601）でない値を持つページを報告する。
   - `updated:`が実行日から**90日以上前**のページを「棚卸し候補」として一覧化する。件数が多い場合は日付の古い順に上位20件までとする。
2. **実在しないパス・ファイルへの言及**
   - `wiki/`・`weekly/`・`obsidian_vault/daily/`の本文に登場するリポジトリ内パス（`docs/...`、`scripts/...`、`.claude/skills/...`、`obsidian_vault/...`等）を抽出し、実際に存在するかを検証する。存在しないものを「実体のない参照」として報告する。
   - 廃止済みのフォルダ名（`areas/`、`resources/`、`projects/`、`docs/`）への言及は特に見落とされやすいため、必ず確認する。
   - ただし**過去の経緯を意図的に記録している箇所**（`wiki/log.md`、[[session-archive|セッション作業アーカイブ]]、および「廃止済み」「削除した」と明記された文脈）は、履歴として正しいため対象外とする。
3. **`source:`が指す原文の消失**
   - frontmatterの`source:`に挙げられた`obsidian_vault/raw/`配下のファイルが実在するかを確認し、失われているものを報告する。同期による消失の早期発見を兼ねる。
4. **同一事実の重複記載**
   - 同じ事実が複数ページに書かれている箇所を検出する。片方だけが更新されて食い違う原因になるため、統合先の候補とともに報告する。
5. **日付スタンプの無い変動する事実**（上記「事実の3形式と日付スタンプ」の禁止形式）
   - 件数・残数・進捗・設定の有無・対応状況・バージョン・「〜済み」「〜中」「〜なし」といった**変動する状態**を、日付スタンプ無しの現在形で書いている行を検出する。日付コンテナ内の記述は対象外（上記の定義を参照）。
   - 判定は文脈に依存するため、**機械的に断定せず候補として挙げる**。同じ語でも不変の事実（例: 「Pythonの`str`はイミュータブルである」）は対象外。
   - 禁止形式を**例として引用している行**（この基準自体を説明する文章など）は、行末に`<!-- freshness: example -->`を置くことで対象外にできる。Markdownとして描画されず、`git grep`で追える。付いているのに何も抑制していない場合は、惰性で残った抑制として併せて報告する。
6. **日付スタンプの鮮度切れ**
   - `（YYYY-MM-DD時点）`等のスタンプが実行日から**30日以上前**の行を「再観測の候補」として報告する。`updated:`の90日（基準1）はページ単位の棚卸し、こちらは行単位の変動する事実が対象であり、目的が異なるため別の閾値を用いる。
   - スタンプがあること自体は正しい書き方である。**古いスタンプを誤りとして報告しない**（何を再観測すべきかが分かる状態は、スタンプが無い状態より健全である）。
   - ポインタが指す先（パス・URL）が実在するかは基準2で併せて検証する。

## 陳腐化の報告フォーマット

報告には必ず「何が」「いつ時点の記述か」「何を確認すれば判定できるか」を含める。

```
### 陳腐化の疑い

- `wiki/例.md`（updated: 2026-03-01、170日経過）
  - 記述: 「設定は docs/example.md を参照」
  - 疑い: `docs/example.md`が実在しない（実体のない参照）
  - 確認方法: 現在の参照先を特定し、記述を差し替えるか削除するかを判断する
```

基準5・6（日付スタンプ）の報告では、確認方法の代わりに**次の3択**を提示する。検出しただけでは記述は健全にならず、どれを選ぶかの判断がユーザーに必要なため。

- **再観測**: 現在の値を確かめ、値とスタンプを更新する。
- **ポインタ化**: 誰も再観測しないなら、その値は重要でなかったということ。値を捨て、真実の所在（ファイル・URL）への参照だけを残す。
- **退避**: 履歴として残す価値があるなら、[[session-archive|セッション作業アーカイブ]]等の日付コンテナへ移す。移った先ではスナップショットとして確定し、以後の再観測が不要になる。

```
### 日付スタンプの無い変動する事実

- `wiki/例.md:31`
  - 記述: 「新規の原因不明な消失は今のところなし」
  - 疑い: 変動する状態を日付スタンプ無しの現在形で書いている（いつ時点の観測かを問えない）
  - 選択肢: 再観測（現状を確認し「（2026-08-21時点）」を付す）／ポインタ化／退避
```

## 制約

- **検出・報告のみとし、自動修正は行わない**（誤修正リスクを避けるため。`CLAUDE.md` 4節 禁止事項）。陳腐化の検出も同様に、報告のみとし記述の書き換え・削除は行わない。
- 修正はユーザー自身の判断に委ねる（手動修正、またはユーザーがClaudeへ個別に修正を指示する）。
- **古いことを誤りと断定しない。** `updated:`が古いだけのページは、内容が今も正しい場合がある。あくまで「再確認すべき候補」として報告する。
- `obsidian_vault/raw/`配下のファイルを編集しない。
- 出力は日本語で書く。
- ファイル入出力時はエンコーディングを UTF-8 で明示する。
- コンソール出力以外で絵文字を使わない。
