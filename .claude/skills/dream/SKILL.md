# dream

`/lint`が検出した違反の履歴から、**何度直しても再発している問題**だけを恒久的な
規約へ昇格させる。1回きりの失敗は規約にしない。これがこのVaultの「実行するたびに
賢くなる」部分にあたる。

## When to use

- ユーザーが `/dream` を実行したとき
- `/lint` を何度か実行し、`memory/violations.jsonl` に記録が貯まったとき

## When not to use

- `memory/violations.jsonl` が空、または`/lint`をまだ1回も実行していないとき
  （先に `python scripts/lint_vault.py --record` を促す）
- 直前の`/dream`提案がまだ未処理で、ユーザーが判断を保留しているとき

## Input

- `python scripts/dream_memory.py` の出力（違反コードごとの再発回数）
- `memory/conventions.md` `memory/lessons.md` の現在の内容
- 必要に応じて `wiki/log.md` の実行履歴

## Output

- `memory/proposals/YYYY-MM-DD-HHMM.md`（提案。**この時点では適用しない**）
- 会話内での提案内容の要約

## 手順

1. `python scripts/dream_memory.py` を実行し、違反コードごとの再発回数を得る。

   このスクリプトは読み取り専用で、数えるだけの決定的な処理をする。**回数を自分で
   数え直さない。** `violations.jsonl`を直接読んで目視で集計するのは誤りである
   （数え間違いが規約の誤昇格に直結するため、集計はコードに委ねている）。

   しきい値を変えたい場合は `--threshold N`（既定3）を使う。

2. 出力の「規約への昇格候補（再発）」に挙がったコードだけを対象にする。
   「単発（様子見）」は今回は扱わない。

3. `memory/conventions.md` を読み、**既に同じ趣旨の規約が載っていないか**確認する。
   載っている場合、それは「規約はあるが守られていない」という別の問題なので、
   規約を増やさず、その旨を提案に書く（言い回しを変えた同義の規約を足さない）。

4. 昇格候補それぞれについて、規約の文言を起こす。次を満たすこと。

   - 1項目1行で、守るべき動作を断定形で書く。
   - 末尾に対応する違反コードを `[CODE]` の形で付ける。検証手段の無い規約は書かない。
   - **タスク固有の答えそのものを書かない。** 「`wiki/overview.md`を`index.md`に
     追加する」ではなく「ページを作ったら`index.md`へ追記する」と一般化する。
     個別の正解を書くと、次に別のページで同じ失敗が起きる。
   - まだ一文に言い切れないものは規約ではなく`lessons.md`向けの学びとして書く。

5. 1回の提案で、`conventions.md`向け・`lessons.md`向けそれぞれ**最大5件まで**とする。
   候補がそれを超える場合は再発回数の多い順に5件を選び、残りは提案の末尾に
   「今回見送った候補」として列挙するに留める。

6. 提案を `memory/proposals/YYYY-MM-DD-HHMM.md` に書き出す。構成は次のとおり。

   ```markdown
   # 提案 YYYY-MM-DD HH:MM

   ## 集計結果
   （dream_memory.py の出力をそのまま貼る）

   ## conventions.md への追加案
   - <規約の文言> [CODE]（N回の実行で再発）

   ## lessons.md への追加案
   - <学びの文言>

   ## 陳腐化したので削除する案
   - <既存の項目と、なぜ不要になったか>

   ## 今回見送った候補
   - <あれば>
   ```

7. 提案の要約を会話に出し、**適用するかどうかをユーザーに尋ねて終了する。**
   ここで`memory/conventions.md`を書き換えてはならない。

## 適用（ユーザーが明示的に承認したときのみ）

ユーザーが「適用して」と明示した場合に限り、次を順に行う。

1. 承認された項目だけを `memory/conventions.md` / `memory/lessons.md` へ追記する。
   ユーザーが一部だけ承認した場合、承認されなかった項目は追記しない。
2. 削除案が承認された場合は該当項目を削除する。
3. `python scripts/dream_memory.py --archive` を実行し、消化した違反記録を
   `memory/violations-consumed.jsonl` へ退避する。これをやらないと、次回以降も
   同じ違反が再発扱いで数え続けられ、同じ提案が繰り返される。
4. 適用した提案ファイルの末尾に、適用日時と適用した項目を追記する。
5. `wiki/log.md` に`/dream`の実行結果（昇格した規約の件数）を記録する。

## 制約

- **既定では提案のみを行い、`memory/`への適用はユーザーの明示的な承認を要する。**
  誤った規約が入ると、以後すべての`/ingest` `/daily` `/weekly`がその誤りに
  引きずられるため、影響範囲の広い操作には人間の承認を挟む。
- 再発回数の集計を自分で行わない（`scripts/dream_memory.py`の出力を使う）。
- 検証手段（違反コード）の無い規約を`conventions.md`に追加しない。
- 個別ページ名・個別トピックへの対処法を規約として書かない（一般化する）。
- 1回の提案はカテゴリごとに最大5件。
- `obsidian_vault/raw/`配下のファイルを編集しない。
- `wiki/`配下のページ内容を編集しない（`wiki/log.md`への実行記録を除く）。
- 出力は日本語で書く。
- ファイル入出力時はエンコーディングを UTF-8 で明示する。
- コンソール出力以外で絵文字を使わない。
