# 第二の脳の運用ナレッジ

このVault（second_brain）を運用する上で、**いつ学んだかに関係なく成り立つ知識**（意味記憶）を集めたページ。「いつ何が起きたか」という時系列の記録は[[session-archive|セッション作業アーカイブ]]、現在進行中の未解決事項は[[session-handoff|セッション引き継ぎメモ]]にある。

ここに書くのは、後のセッションが**参照しに来る価値のある事実**に限る。会話の流れの中でしか意味を持たない記述は書かない。

## 仕組みに関するQ&A

- **Claude Code CLIは毎回`raw/`の全mdファイルを読むか** → 読まない。`/query`は`wiki/`中心を走査し、`/ingest`のみ`raw/`の未処理ファイルを読む。
- **`wiki/`への整理はObsidian標準機能かPythonコードか** → どちらでもない。Claude Code（AI）が`/ingest`実行時にその場で読解・要約・生成している。
- **Claude Desktop（デスクトップアプリ）からObsidianの情報を取得できるか** → 標準では不可。MCPサーバー（filesystem MCP等）を設定すれば読み取り可能。`.claude/skills/`のSkillsはClaude Code CLI専用。
- **`raw/`ノートを自動的に関連付ける方法はあるか** → 可能。①Obsidianプラグイン（Smart Connections等。埋め込みベースの類似度検出で`raw/`を書き換えない）②Python自作（embeddingやキーワード共起解析、結果は`wiki/`側に出力）の2案。**①を採用**し、ローカル完結の埋め込みモデルを使う方針。

## 採否が確定した検討事項

| 対象 | 判断 | 理由 |
|---|---|---|
| Smart Connections（Obsidianプラグイン） | **採用** | `raw/`を書き換えずに埋め込みベースで関連ノートを提示できる。ローカル完結でAPIキー不要 |
| `defuddle`を`/ingest`の前処理に使う | **見送り確定** | Node.js依存の追加コストに対し、恩恵が`raw/articles/`に限定されデメリット優位 |
| LangGraph等のワークフローグラフ基盤 | **見送り** | 手動トリガー・単一ユーザーの本Vaultには過剰。並列/条件分岐/リトライを要する規模ではない |
| 外部グラフDB（Neo4j等）による知識グラフ | **見送り** | 61ページ規模には過剰投資。wikilink運用の徹底とSmart Connectionsで代替できる |
| 埋め込みモデルにAPIキー課金型（OpenAI等）を使う | **不採用** | ローカル完結を優先する方針。既定の`transformers - TaylorAI/bge-micro-v2`で足りる |

## Smart Connectionsの設定に関する知識

- 設定画面は**「Connections」タブ（結果表示の見た目）と「Smart Environment」タブ（埋め込みモデル・除外フォルダ等の実体設定）が分かれている**。両者を混同しやすいため、設定を案内する際は現在どちらのタブにいるかを先に確認する。
- PRO機能（紫バッジ）は有料版専用で、無料版では使えない。無視してよい。
- 埋め込みモデルの既定値は`transformers - TaylorAI/bge-micro-v2`（Provider: transformers）。ローカル完結・APIキー不要のため既定のままでよい。
- 埋め込みキャッシュ（`.obsidian/plugins/smart-connections/`・`.smart-env/`）は再生成可能なローカルデータのため`.gitignore`で除外している。

## Vault構造に関する確定事項

- ObsidianアプリのVaultルートは**`obsidian_vault/`**であり、リポジトリ直下ではない。根拠は`.obsidian/`の実在位置と、`obsidian_vault/.obsidian/daily-notes.json`が`"folder": "daily"` `"template": "templates/daily-note.md"`というVaultルート相対パスを持つこと。
- `wiki/`・`weekly/`はVault外に置くAI運用専用ディレクトリ。Obsidianアプリからは見えず、wikilinkも解決されない。これは**現状維持と決定済み**（詳細は[[second-brain-vault構成|second_brainのディレクトリ構成]]）。

## 作業の進め方に関する教訓

- **削除・大規模変更の指示を受けたら、着手前に`git grep`等で影響範囲（他のSkills・スクリプト・ドキュメントへの波及）を洗い出す。** `areas/`・`resources/`・`projects/`廃止の際に有効だった手順。
- **削除指示のスコープは確認質問で絞り込む。** 過去に「wiki/・weeklyも削除」と読める指示があったが、確認した結果`areas/`・`resources/`のみが対象と判明した実績がある。
- ローカル（Windows PC）とリモートセッションの双方から同じブランチへpushする運用のため、**作業開始前に必ず`git fetch`＋`git status`で差分を確認する**（過去に双方pushでコンフリクトが複数回発生）。
