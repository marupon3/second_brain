00 / OVERVIEW

連携の全体像

このVaultは、Obsidian（ローカルファーストのノートアプリ）が Markdownファイルを表示・編集する画面を担当し、Claude Code が obsidian_vault/raw/ の生データを読んで wiki/ に知識を構造化する役割分担で動きます。 サーバーは持たず、すべてローカルのファイルシステム上で完結します。

POINT Claude Codeが書いたMarkdownは、そのままObsidianのwikilink（[[ページ名]]）として認識されます。2つのツールの間に変換や同期作業は必要ありません。
01 / WALKTHROUGH

実行手順

初回セットアップから、実際にAIがノートを生成するところまでを順番に進めます。

1

依存ツールを確認する

Python 3.11.9・Git・uv・pip が揃っているかをチェックします。

PS> python scripts/check_env.py
[OK] Python 3.11.9
[OK] Git: git version 2.54.0.windows.1
[OK] uv: uv 0.12.2
[OK] pip: pip 26.2.1
[OK] Node.js: v26.6.0
すべての必須ツールを確認できました。
要確認 [NG] が出た項目は、そのツールをインストール（または対応バージョンに変更）してから再実行してください。uv が見つからない場合の対処は「エラー時の対策」を参照。
2

Vaultのディレクトリ構造を生成する

obsidian_vault/raw/ wiki/ obsidian_vault/daily/ などの構造を作ります。既存ファイルは上書きしないので、何度実行しても安全です。

PS> python scripts/setup.py
作成: obsidian_vault/raw/articles
作成: obsidian_vault/raw/notes
作成: wiki
作成: obsidian_vault/daily
... (中略) ...
Vaultディレクトリ構造の生成が完了しました。
3

CLAUDE.md を確認・カスタマイズする

Claude Codeがこのフォルダで作業する際に必ず読み込む運用マニュアルです。フォルダの役割・書き方ルール・禁止事項が定義されています。必要であれば自分の運用に合わせて編集してください。

4

Obsidianでこのフォルダを開く

Obsidianを起動し、「フォルダをVaultとして開く」からこのディレクトリ（second_brain）を選択します。

POINT Vaultとして開いた時点で wiki/ のwikilinkは自動でリンクとして機能し、標準機能の Graph View でページ同士のつながりを見られます。プラグインの追加設定は不要です。なお、ユーザーが直接書き込むraw/やdaily/などはobsidian_vault/サブフォルダの配下にまとまっています（Vaultのルート自体はsecond_brain/のまま）。
5

Claude Codeをこのディレクトリで起動する

PS> cd second_brain
PS> claude
6

基本のSkillsを試す

まず obsidian_vault/raw/notes/ にメモを1つ置いてから、Claude Code上で以下を試します。

> /ingest   # obsidian_vault/raw/の新規ファイルを読み、wiki/に構造化ページを生成
> /daily    # 今日のDaily Noteを生成・更新
> /weekly   # 直近7日分を要約したWeekly Reviewを生成
> /lint     # リンク切れ・矛盾・孤立ページを検出（自動修正はしない）
> /query    # Vault全体を対象に質問応答
POINT ファイルはObsidianの外（Claude Code）から書き換わります。Obsidianは通常ファイルの変更を自動検知して再読み込みしますが、反映されない場合はそのノートを一度閉じて開き直してください。
02 / TIPS

使いこなしのTips

日常運用でつまずきにくくするための、小さな習慣です。

TIP 01

ページ名は日本語のままでよい

wikilink（[[ページ名]]）は日本語ファイル名にそのまま対応します。無理に英語化する必要はありません。

TIP 02

Graph Viewで抜け漏れに気づく

左側のGraph Viewを定期的に眺めると、他とつながっていない孤立ページが視覚的にわかります。/lintの結果と合わせて確認すると効果的です。

TIP 03

「人間メモ」欄に書く習慣をつける

Daily Noteの「## 人間メモ」セクションはAIが上書きしない設計です。自分の一次情報は必ずこの欄に書きましょう。

TIP 04

raw/ は「投入したら触らない」

obsidian_vault/raw/配下は不変ソースという前提でAIが要約します。書いた内容を後から編集すると要約との整合が崩れるので、直したい場合は新しいファイルとして追加しましょう。

TIP 05

こまめにgit commitする

本Vaultはクラウド自動バックアップを前提としません。Daily Note生成後などの節目でコミットしておくと、後から安心して見返せます。

TIP 06

.env はコピーしてから使う

秘密情報は.env.exampleを.envとしてコピーしてから書き込みます。.env自体はgitignore済みでコミットされません。

03 / TROUBLESHOOTING

エラー時の対策

実際に発生しやすい5パターンと、その初動対応です。クリックで詳細を開けます。

SETUPcheck_env.py が [NG] を出して終了する（終了コード1）▶
症状実行結果に [NG] の行が出て、「必須ツールの不足、またはバージョン不一致があります」と表示される。
よくある例uv が見つかりません（PATHに存在しません）
対処
  1. どのツールが[NG]かを確認する（Git / uv / pip / Python 3.11.9のいずれか）。
  2. uvの場合、PowerShellで次のいずれかを実行してインストールする。 
    PS> powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
# もしくは
PS> pip install uv
  3. インストール後はPowerShellを新しく開き直し（PATH反映のため）、uv --versionで確認する。
  4. python scripts/check_env.pyを再実行し、すべて[OK]になることを確認する。
SETUPsetup.py が「対象パスがディレクトリではありません」で終了する▶
原因指定した対象パスが、既に存在する「ファイル」と衝突している。
対処
  1. 指定したパスが本当にディレクトリとして使える場所かを確認する。
  2. 正しいディレクトリパスを指定し直して再実行する。
整合性raw/ がAIによって編集された疑いがある▶
原因obsidian_vault/raw/は人間のみが編集する不変ソースという設計だが、想定外の変更が入った可能性。
対処
  1. git diff -- obsidian_vault/raw/で変更内容を確認する。
  2. 意図しない変更なら、コミット前はgit checkout -- obsidian_vault/raw/<該当ファイル>、コミット後はgit revertで復元する。
  3. CLAUDE.mdの「禁止事項」に obsidian_vault/raw/ 編集禁止が明記されているか確認する。
運用/lint がリンク切れ・矛盾を検出した▶
仕様/lintは検出・報告のみを行い、誤修正を避けるため自動修正は行いません。
対処
  1. 実行結果のレポート（wiki/log.md、件数が多い場合はwiki/lint-report.md）を確認する。
  2. 手動で修正するか、Claude Codeに個別のページを指定して修正を指示する。
性能応答や処理が明らかに遅い▶
目安ingest 30〜90秒 / query 10〜30秒 / lint 1〜3分 / daily 10秒以内。これを大きく超える場合が対象。
原因本Vaultはインデックスを持たず、ファイルシステムを直接走査する設計のため、wiki/のページ数が増えるほど遅くなる。
対処
  1. wiki/配下のファイル数を確認する。
  2. 大規模Vaultでは、/query実行時にフォルダやトピックで範囲を絞って質問する。
04 / GOVERNANCE

Obsidian管理者の役割と運用

このVaultの「管理者」＝日常的にObsidianを使う本人です。AIが書き換えてよい領域と、人間だけが責任を持つ領域が明確に分かれています。

フォルダ管理者役割
obsidian_vault/raw/ 人間のみ 不変の原文・スクラップ。articles / notes / pdfs / personalに分類して投入する。
wiki/ AI obsidian_vault/raw/から生成した要約・概念・エンティティページ。index.md / log.mdを含む。
obsidian_vault/daily/ 人間+AI 日次ノート。「人間メモ」「AI生成」「タスク」のセクションで責任範囲を分離。
weekly/ AI 週次レビュー。/weekly実行で生成される。
obsidian_vault/private/ 人間のみ パスワード等の非公開情報を含むローカル専用ノート。.gitignoreで除外され、リモートには一切push・同期しない。
obsidian_vault/templates/ 人間+AI Daily Note等の固定テンプレート。

管理者が守るべき禁止事項

  • obsidian_vault/raw/配下はAIに編集・削除させない（不変ソースとして扱う）。
  • ファイルの削除・大規模な書き換えなど破壊的操作は、実行前に必ず確認する運用を徹底する。
  • APIキー等の秘密情報はMarkdownやコードに直書きせず、.envまたは環境変数で管理する。
  • /lintが検出した問題を、確認なしに自動修正させない。

バックアップとリストア

クラウド同期への依存は前提としないため、バックアップは以下のいずれかで自分の手で行います。

  • 取得方法：Gitコミット、またはVaultフォルダ全体のコピー。
  • 推奨頻度：目安として日次のGitコミット（設計上の必須要件ではなく運用上の推奨）。
  • リストア：Gitの場合はgit cloneまたは対象コミットへのgit checkout。フォルダコピーの場合はバックアップ先を丸ごと復元。
