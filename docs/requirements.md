# second_brain 要件定義書

## 1. 目的

Claude CodeとObsidianを組み合わせ、個人が蓄積する生データ（記事・メモ・PDF等）から、AIが構造化された知識ベース（Wiki）を継続的に生成・維持する、ローカル完結型の「第二の脳（Second Brain）」を実現する。

## 2. 想定利用者

- 本Vaultを日常的に使う個人（単一ユーザー）。複数ユーザーでの共有・同時編集は想定しない。
- 利用者は日本語話者であり、プロンプト・ノート・ファイル名は日本語を標準とする。

## 3. 前提環境

- OS: Windows 11（64bit）
- Python: 3.11.9（厳密固定）
- パッケージ管理: `uv`（主）、`pip`（フォールバック）
- Git（バージョン管理・変更履歴の唯一の正）
- Claude Code（Pro以上のプラン）
- Obsidian（最新安定版）
- サーバー・常駐プロセスを持たないローカル完結型。デプロイ・監視基盤は無い。

## 4. 機能要件

### 4.1 データの投入・分類（`obsidian_vault/raw/`）

- 人間が記事・メモ・PDF・個人的な資料を`articles/` `notes/` `figures/` `personal/`に分類して配置できること。
- `raw/`配下は人間のみが書き込む不変ソースとして扱い、AIによる編集・削除を禁止すること（機構的強制は非機能要件を参照）。

### 4.2 知識ベースの自動構造化（`/ingest`）

- `raw/`配下の未処理ファイルを検出し、内容を要約・構造化して`wiki/`にMarkdownページとして生成・更新できること。
- ページ間の関連をObsidian形式のwikilink（`[[ページ名]]`）で表現すること。
- PDFはテキスト抽出のみを対象とし、画像・図表本体の保持は対象外とすること（将来拡張）。
- 大量ファイル（目安20件超）を処理する場合、サブエージェントへの分担・集約による並列処理ができること。
- 生成・更新のたびに`wiki/index.md`（索引）・`wiki/log.md`（実行記録）を更新すること。

### 4.3 日次ノート（`/daily`）

- 当日のDaily Noteを`obsidian_vault/daily/YYYY-MM-DD.md`に生成・更新できること。
- 「人間メモ」「AI生成」「タスク」のセクションを分離し、人間が編集したセクションをAIが上書きしないこと。
- 前日までの未完了タスクを当日ノートへ引き継げること。

### 4.4 週次レビュー（`/weekly`）

- 直近7日分のDaily Noteを要約し、`weekly/YYYY-Www.md`（ISO週番号）にWeekly Reviewを生成・更新できること。
- 完了・未完了タスク、主要トピックを集約すること。

### 4.5 整合性・鮮度チェック（`/lint`）

- `wiki/` `obsidian_vault/daily/` `weekly/`配下のリンク切れ・孤立ページ・矛盾を検出し報告できること。
- frontmatterの`updated:`の形式・鮮度（90日超）、および本文中の日付スタンプの鮮度切れ（30日超）を検出できること。
- 実在しないパスへの参照、`source:`原文の消失、同一事実の重複記載を検出できること。
- **検出・報告のみを行い、自動修正は行わないこと**（誤修正リスクの回避）。

### 4.6 質問応答（`/query`）

- ユーザーの質問に対し、`wiki/`を中心に`obsidian_vault/daily/` `weekly/`を横断的に探索して回答できること。
- 回答には参照元ページをwikilinkで明示すること。
- ユーザーの了承がある場合のみ、回答を`wiki/`へ新規ページとして保存できること。

### 4.7 記憶の階層管理

- `wiki/`配下の記録を性質に応じて分離すること。
  - `session-handoff.md`: 作業中の未解決事項（作業中記憶）
  - `第二の脳の運用ナレッジ.md`: いつ学んだかに依存しない確定知識（意味記憶）
  - `session-archive.md`: 過去の作業の時系列記録（エピソード記憶）
  - `log.md`: Skills実行記録
- セッション開始時に読むべきページを`session-handoff.md`のみに集約できる状態を維持すること。

### 4.8 記憶の削除・陳腐化対応

- 記憶の削除は、影響範囲の洗い出し・ユーザー承認・実削除・（必要なら）経緯記録という明示的な手順を経ること。取り消し線等で本文に痕跡を残さず、履歴はGitコミットで追跡すること。
- 変動する事実（件数・進捗・設定有無等）は、日付スタンプ・ポインタ・日付コンテナ退避のいずれかの形式で記述し、`/lint`で検出できること。

## 5. 非機能要件

### 5.1 セキュリティ（機構的強制）

ガイダンス（`CLAUDE.md`の記述）のみでは順守が保証されない、取り返しのつかない操作は、Claude CodeのPreToolUse Hookで機構的にブロックすること。

| 要件 | 実現方式 |
|---|---|
| `raw/`配下へのAIによる編集・削除を防止する | `block-raw-edit.sh`（Edit/Write/NotebookEdit）、`block-raw-bash.sh`（Bash） |
| APIキー等の秘密情報がファイルに書き込まれることを防止する | `block-secret-write.sh`（Edit/Write/NotebookEdit） |
| 破壊的Git操作（force push・reset --hard等）を防止する | `block-dangerous-git.sh`（Bash） |
| `obsidian_vault/private/`の非公開情報をAIが読み取ることを防止する | `.claude/settings.json`の`permissions.deny` |

### 5.2 データ保全・可搬性

- 秘密情報（パスワード等）は`obsidian_vault/private/`に隔離し、`.gitignore`でリモート同期対象から除外すること。
- 全Markdownファイルをコミット単位でGit管理し、変更履歴を追跡・切り戻しできること（`git revert`を標準手順とする）。
- バックアップはGitコミットまたはVaultフォルダ全体のコピーで実現できること。

### 5.3 文字コード・言語

- すべてのMarkdownファイルはUTF-8で保存すること。
- Skillsの出力は日本語を標準とすること。

### 5.4 性能目安

- `/ingest`: 1件あたり30〜90秒
- `/query`: 10〜30秒
- `/lint`: 数百ページ規模で1〜3分
- `/daily`: 10秒以内
- Vaultはインデックスを持たずファイルシステムを直接走査する設計のため、ページ数増加が処理時間に直結する。千ページ超では対象範囲を絞ることを推奨する。

### 5.5 実行トリガー

- 全SkillsはClaude Code CLI上での手動コマンド実行（`/ingest`等）をトリガーとし、スケジュール実行は行わない。

## 6. スコープ外（将来拡張）

- PDF内の画像・図表本体を`wiki/`側に保持する機能。
- 複数ユーザーでのVault共有・同時編集。
- サーバーサイドでの常時稼働・自動実行基盤。
